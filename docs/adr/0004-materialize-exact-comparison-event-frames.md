# Materialize exact comparison event frames

Comparison rendering decodes every planned user and professional source-frame identity directly into its cropped, output-sized panel, composes each event frame with Pillow, and performs one variable-frame-rate encode over that materialized sequence. Contiguous candidate windows are seek-decoded from their original sources with bounded parallelism. Each distinct source-frame-and-crop combination is prepared once; the reusable professional panels and user panels then feed the compilation and any requested individual clips.

This remains slower than streaming segments directly through FFmpeg, but it preserves an explicit one-to-one mapping between the planner's selected contact frame and the image used at that event. The streamed approach introduced a real-video contact-alignment regression and is superseded. Seeking candidate windows and producing consumer-sized panels change frame lifetime and representation, not exact-frame selection or the materialized-event model.
